# 五子棋模型擂台

擂台调度器在 Node.js 进程中运行，创建两个 AI 座位的五子棋对局。每个座位可配置为自动 API 选手或外部 MCP 选手；对局规则和合法性仍由游戏引擎判定，网页可以实时观战。

## 浏览器擂台

打开 `/arena`，按新手指引选择创建对局或输入朋友给的口令。创建者可以自己下棋、使用浏览器 API、OpenCode 或其他 MCP；对手可以是朋友或 AI。邀请朋友时，复制对方座位的链接或口令；朋友打开链接或输入口令后，可选择自己落子或使用自己的 AI。链接中的口令放在 URL 片段中，页面读取后会从地址栏清除；口令仍是控制座位的凭证，只能分享给信任的人。本机 `127.0.0.1` 链接不能发给其他设备，远程朋友需要公开可访问的 HTTPS 地址。

创建后，MCP 座位显示专用连接地址和可复制提示词；对局页也显示可以点击的棋盘。API Key 只保存在当前页面的内存中，浏览器直接向所选接口发请求；切换服务商、退出或刷新会清除密钥。页面关闭时浏览器驱动的选手停止，MCP 客户端独立运行。可以在页面中展开并保存自己的座位口令，之后通过「输入口令」重新加入；使用 API 时需重新输入密钥。

选择「OpenCode · MCP」时，页面会为该座位生成 OpenCode 远程 MCP 配置和提示词。将 `mcp` 配置合并到项目 `opencode.json` 或全局 `~/.config/opencode/opencode.json`，保留文件中已有的配置；启动或重新打开 OpenCode 后可用 `opencode mcp list` 检查连接，再发送提示词。该座位 URL 本身包含口令，配置文件不应提交到公开仓库。OpenCode 使用自己配置的模型与服务商账号，游戏页面不需要它的 API Key；对方在另一台设备上时必须使用对方能访问的服务器地址，本机 `127.0.0.1` 不能直接分享。

支持 MiniMax、DeepSeek、阿里云百炼、火山方舟、腾讯云 TokenHub 的 OpenAI Chat Completions 接口预设，也可填自定义兼容接口的完整 URL 或 Base URL。自定义地址必须是 HTTPS（本机地址可用 HTTP），API Key 会直接发送给填写的地址，请自行确认可信。各服务商套餐、模型和浏览器跨域策略不同；TokenHub 的预检在测试时未通过，预设并不保证能够从浏览器调用。预设只对已知支持的服务商设置思考强度，其余使用服务商默认设置。

公开开局默认关闭。测试环境可配置 `PUBLIC_ARENA=1`，开启不需要管理员口令的五子棋擂台开局，并有每小时全站 60 局的基本限制；管理员仍可使用原站点口令。反向代理时需设置 `PUBLIC_ORIGIN` 为准确的 HTTPS 网站源（不带路径或末尾斜杠），以验证来源并生成正确的 MCP 链接。该限额不能替代公网部署前的安全审查、独立用户配额和针对恶意流量的保护；不要将本地测试口令用于公网。浏览器创建的棋局保存在 Worker 的原有对局存储，**暂不自动写入**下方的 Node 调度器 SQLite 统计数据库。

## 启动

需要带 `node:sqlite` 的 Node.js（建议 22.13 或更高版本）及已安装的工作区依赖，并先启动本项目的 Worker。将 `apps/worker/arena/config.example.json` 复制到项目外的私有位置，配置两个 `players`：

- `api`：配置 `endpoint`、`model`、`keyEnv`。接口必须兼容 OpenAI Chat Completions 的请求和响应格式，且接收 JSON 格式的模型输出。不同服务商未必兼容；不要假设所有模型均可直接使用。
- `mcp`：外部 AI 座位。启动后终端打印该座位的专用 MCP 地址，把它交给这个选手。座位地址含口令，只能发给该选手，不要公开或提交。

两个座位都可填写 `provider`；MCP 座位也可填写 `model`，用于比赛记录。调度器无法验证外部客户端实际使用的型号，未填写时数据库留空。

API 座位可选填 `reasoningEffort`，会作为 `reasoning_effort` 发送给接口。MiniMax-M3.1-Flash 可填 `low`、`medium`、`high`、`xhigh` 或 `max`，不填时默认 `max`；该模型不支持关闭思考。其他服务商是否支持以及可用值以其接口文档为准。

可以两个都是 `api`、两个都是 `mcp`，或者各一个。黑棋是第一个座位。将示例地址替换为实际服务地址。远程游戏服务器和模型接口要求 HTTPS；仅本机允许 HTTP。

通过环境变量提供密钥，而非写入配置文件：

```bash
export RAIN_GO_TOKEN='你的站点口令'
export MODEL_A_KEY='模型 A 的 API 密钥'
# 如有第二个 API 座位，也设置其 keyEnv 对应的环境变量
node apps/worker/arena/run.mjs /私有路径/arena.json
```

终端会显示观战地址和外部选手连接地址。`recordFile` 可选，追加 JSONL 格式的比赛事件、API 用量（如接口返回）、结束时的完整走法；不包含密钥和座位链接。它不会自动获取外部客户端的用量或模型版本，输出路径及其已有权限由运行者管理。

擂台同时写入 SQLite 数据库，默认路径为 `~/.local/share/rain-go/arena.sqlite`，可通过配置文件的 `databaseFile` 更改。它记录对局状态、对手的型号及接入方式、走法、每次运行的配置和 API 调用用量；API 密钥、座位口令和连接地址不会保存。对局走法由调度器在运行时同步，调度器意外中断后可通过恢复对局补齐。MCP 客户端的推理用量和思考时间无法由此调度器测量。该数据库属于运行调度器的机器，普通网页或 MCP 创建但未由擂台调度器管理的对局不会自动进入它；服务器原有对局存储独立保留。

查询记录：

```bash
node apps/worker/arena/history.mjs              # 列出比赛
node apps/worker/arena/history.mjs <对局ID>     # 查看双方、走法和运行记录
# 使用自定义数据库时：ARENA_DATABASE=/路径/arena.sqlite node apps/worker/arena/history.mjs
```

模型不返回合法 JSON 或合法坐标时会按 `maxAttempts` 重试；API 请求超时或失败时，调度器停止，棋局保留。停止后，在配置中加入 `"gameId": "对局ID"`，以原顺序重新配置选手并重启即可继续。恢复仅支持新建的对等信息模式棋局；旧棋局不会被自动改造。外部 MCP 座位等待时间不设上限，停止进程不会判负。该程序应保持运行；它不是后台服务或自动重启管理器。

## 模型看到什么

擂台创建对等信息模式的棋局。API 选手通过自己座位的 MCP `get_state` 获取状态，调度器将该工具返回的文字原样传给模型；外部 MCP 选手调用相同工具得到同一格式。双方收到相同的规则、棋盘坐标、轮次、上一步和结果，只有各自执棋颜色不同。不包含获胜点、威胁点、合法走法排序或对手聊天。每次都是完整快照，规则也会重复发送。

API 选手需用 JSON 输出走法；MCP 选手通过 `play` 工具发送坐标。这些操作格式不同，但不会增加棋局信息。非法走法会反馈错误；API 选手按配置重试，外部 MCP 客户端自行决定是否重试，因此重试政策、客户端系统提示与历史仍可能不同，比赛不能视为完全控制所有上下文条件的基准。普通对局保留原有文字描述。现阶段模型配置只支持此兼容接口，尚无网页上的配置管理或循环赛。
